```zig
const std = @import("std");
const guillotine = @import("guillotine_mini");
const voltaire = @import("voltaire");

pub fn main() !void {
    const Evm = guillotine.Evm(.{});
    var vm: Evm = undefined;
    try vm.init(std.heap.page_allocator, null, .CANCUN, null, voltaire.ZERO_ADDRESS, 0, null);
    defer vm.deinit();

    // PUSH1 0x2a  PUSH1 0x00  MSTORE  PUSH1 0x20  PUSH1 0x00  RETURN
    const target = voltaire.Address.fromU256(0x42);
    try vm.code.put(target, &.{ 0x60, 0x2a, 0x60, 0x00, 0x52, 0x60, 0x20, 0x60, 0x00, 0xF3 });

    const result = vm.call(.{ .call = .{
        .caller = voltaire.ZERO_ADDRESS,
        .to = target,
        .value = 0,
        .input = &.{},
        .gas = 100_000,
    } });
    // result.success == true, result.gas_left == 99_982 (18 gas used), output == 32-byte word 0x2a
}
```

## Why Guillotine Mini exists

Production EVMs optimize for block throughput: bytecode is fused into superinstructions, gas is hoisted across basic blocks, and the correspondence to the specification disappears. That is the right trade for a mainnet node and the wrong trade when you need to verify what the Ethereum specification actually requires.

Guillotine Mini takes the opposite side:

- **Spec-first.** The Python [`execution-specs`](https://github.com/ethereum/execution-specs) are the authority. Gas is charged in the same order, in the same place.
- **Small enough to read in an afternoon.** State orchestration lives in `src/evm.zig`; the bytecode loop lives in `src/frame.zig`; external state crosses an 11-pointer vtable in `src/host.zig`.
- **Three delivery surfaces.** Use it as a Zig module, link `libguillotine_mini.a` over C FFI, or instantiate `guillotine_mini.wasm` (a WASI Preview 1 reactor with BN254, BLS12-381, SHA256, and KZG compiled in).
- **Zero hidden ownership.** Transaction-scoped allocations live in an arena owned by `Evm` and are released together in `deinit()`.

## What it is not

Guillotine Mini is an execution engine, not a full node. Block headers, transaction signatures, the mempool, JSON-RPC, and devp2p live one layer up in [Guillotine](/stack). Public APIs are pre-1.0 and may shift between revisions.

## Current status

- **Native Zig (`0.15.2`):** `zig build`, `zig build native`, and `zig build test-trace` pass cleanly. Core EVM unit tests pass; the 6 client/trie fixture tests in `zig build unit` require the optional `ethereum-tests` submodule.
- **WebAssembly (`wasm32-wasi`):** `zig build wasm` builds `zig-out/bin/guillotine_mini.wasm` (WASI Preview 1 reactor with linked Rust crypto), and `zig build test-wasm` verifies execution, reverts, logs, SHA256, BN254 pairing, and BLS12-381 precompiles on Node 22+.
- **Hardforks:** Frontier through Osaka, including EIP-1153 transient storage, EIP-4844 blobs, EIP-6780 `SELFDESTRUCT`, EIP-7702 set-code delegation, BLS12-381 (`0x01`–`0x13`), Osaka `CLZ` (`0x1E`), and `P256VERIFY` (`0x0100`).
